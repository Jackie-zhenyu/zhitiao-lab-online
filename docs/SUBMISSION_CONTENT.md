## 第 02 页｜问题背景：实验结束，分析工作才刚开始

控制实验常以一份 CSV 结束，但一份可解释的实验结论仍需要回答连续的问题：哪一列是时间，单位是秒还是毫秒？目标与实测是否同单位？记录是否发生了丢点或时间重置？这一次响应究竟更快，还是只是观察窗口不同？

本项目针对以下工作流风险设计，**这些是需求分析中的问题假设，并非已完成的用户调研统计**：

| 工作环节 | 容易出现的问题 | 对结论的影响 |
| --- | --- | --- |
| CSV 整理 | 列名、编码和单位不一致 | 同一计算可能产生不同数量级 |
| 曲线观察 | 缺失值、重复时间或重置被忽略 | 把记录问题当作系统动态 |
| 指标计算 | 用样本均值替代时间加权、混算多阶跃 | 非等间隔记录的结果失真 |
| A/B 比较 | 按文件首行对齐、窗口或负载不同 | 差异被错误归因于参数修改 |
| AI 解释 | 回复中的数值没有实际计算来源 | 内容流畅但不可复查 |
| 报告整理 | 页面改配置后继续使用旧结果 | 报告难以复现 |

智调 Lab 将这些确认和核对步骤连成一个工作台，把分析依据和限制与结果一起交付。

视觉建议：以“原始日志 → 口径确认 → 数值证据 → 实验结论”四步图呈现，避免未经验证的效率提升百分比。

## 第 03 页｜目标用户与需求：服务一次完整的实验复盘

**首要用户：**正在完成自动控制、电机控制或机器人课程实验的大学生。典型任务是解释一次阶跃响应、比较两次参数实验，并提交有数据依据的实验报告。

**延伸用户：**指导实验的教师和助教，以及开展离线日志复盘的学生项目组。前者需要核对指标口径与分析过程，后者需要保存可复查的实验上下文。当前版本不包含教师账户、班级管理或团队协作系统。

| 用户任务 | 产品响应 | 完成的判据 |
| --- | --- | --- |
| 看懂一份日志 | 字段/单位确认、质量检查、交互曲线 | 能定位原始行和实际时间范围 |
| 量化单次响应 | 用户确认阶跃、基线及阈值后计算 | 每项指标有定义、状态与来源 |
| 比较两次实验 | 独立快照、阶跃对齐、共同窗口 | 可比性和条件限制同时展示 |
| 用自然语言追问 | 可选模型选择白名单工具 | 结论引用本轮真实工具结果 |
| 完成报告与复查 | HTML/JSON/CSV、项目包恢复 | 报告快照一致，恢复时重新核算 |

最小输入是包含 `time`、`target`、`actual` 的 CSV。`control`、`p_term`、`i_term`、`d_term` 为可选字段。设备、负载或单位不明确时允许保留未知状态，不自动补写。

## 第 04 页｜产品全景：一个工作台，三条主要入口

应用保留“实验分析”“实验对比”“报告预览”三个主要入口，AI 分析位于独立区域。左侧管理实验、映射、单位、有效区间和规则；主区域呈现数据质量、指标、曲线和异常证据。

**完整操作路径：**

1. 上传 CSV 或加载明确标注来源的示例。
2. 核对推荐映射，确认时间单位、物理量及目标/实测单位一致。
3. 查看质量问题，必要时明确选择连续有效区间。
4. 确认单次阶跃、基线和评价参数，查看程序计算结果。
5. 展开事件证据并聚焦对应时间或原始行。
6. 保存独立实验快照，核对条件并计算 A/B 对比。
7. 可选：授权有限摘要后进行 AI 追问。
8. 导出报告和项目包，下次校验后继续。

不配置模型仍可完成第 1–6、8 步。项目包需主动下载；刷新、关机或会话回收前未保存的数据可能丢失。

## 第 05 页｜可信输入：先确认数据，再解释实验

导入支持 UTF-8、UTF-8 BOM，并提供编码和分隔符手选。默认单文件上限 20 MiB、最多 200000 条数据记录；限制在读取和解析过程中执行，不先无限读取。用户可以在界面调整导入限制。

系统推荐字段映射，但只有用户确认才生效。时间支持秒和毫秒，内部统一为秒；目标和实测必须确认同单位。脉冲不会自动转换为角度，也不会猜测编码器分辨率。

质量检查定位缺失、非数值、无穷值、重复时间、倒退、疑似时间重置和间隔异常。默认采样间隔规则是正相邻时间差中位数的 `[0.5, 2.0]` 倍，可配置。**规则命中表示需要检查，不等于设备故障。**

原始字节保持只读并保留 SHA-256。系统不静默排序、删除、填补、平滑或跨断点插值。有阻断问题时停止直接分析，允许用户选取原始行连续且时间单调的有效片段。

证据图：质量问题示例的“问题位置 + 连续有效区间”界面，保留“解析函数合成数据”标签。展示一条缺失或重复时间证据，不把人为构造的问题称为真实设备故障。

## 第 06 页｜程序计算：指标定义与适用范围公开

一般跟踪指标使用完整有效选段及实际时间戳。设 `e(t)=target(t)−actual(t)`，区间为 `[ta,tb]`：

| 指标 | 本版定义 | 单位 |
| --- | --- | --- |
| 时间加权 RMSE | `sqrt(∫e²dt / (tb−ta))` | 物理单位 U |
| IAE | `∫abs(e)dt` | U·s |
| 最大绝对误差 | 选段采样点的 `max(abs(e))` | U |
| 末段平均偏差 | 默认最后 10% 时间窗口的时间加权平均误差 | U |

积分使用实际时间戳的复合梯形公式，支持非等间隔采样。末段平均偏差不等于已有稳定性证据的“稳态误差”；采样最大误差也不能推断采样之间漏掉的峰值。

单阶跃记录 `t0、r0、r1、y0`。`y0` 来自有效阶跃前基线；无基线时必须由用户明确提供。设 `q=(actual−y0)/(r1−y0)`：上升时间为首次从 10% 达到 90% 的时间差；超调量为 `max(0,max(q)−1)×100%`。

**响应采用相对于目标值的归一化约定，不是按实测稳态值归一化的标准 stepinfo。** 目标调节时间对应最终连续进入 `abs(actual−r1)≤max(0.02×abs(r1−y0), absolute_tolerance)` 的起点，默认还需至少 0.5 s 后续观察。它只表示在本次观测区间内满足。

缺少交点、短记录、静态目标或数据断点时，结果以明确状态及原因返回，不能用 0 冒充成功。完整口径：`docs/METRICS.md`。

## 第 07 页｜异常证据：看见现象，也看见不确定性

规则检测四类现象：稳定目标附近持续波动、控制输出持续接近确认上下限、测量突变/变化率异常、数据记录异常。阈值公开，并区分默认值与用户值；涉及持续时间和时间占比时按实际时间计算。

每条事件保留 `event_id`、实验 ID、起止时间或原始行、检测规则、阈值、观测量、关联图表与限制。用户点击证据卡，图表聚焦对应片段，而性能分析区间保持原确认值。

| 能确认的现象 | 仍不能直接确认的原因 |
| --- | --- |
| 满足规则的持续波动 | 不能仅据此判断某个 PID 参数错误 |
| control 接近已确认限值 | 不等于确认积分饱和 |
| 无物理上限时的统计突变候选 | 不等于传感器故障 |
| 时间缺失或重置等记录异常 | 不能仅据日志确定设备、通信或记录程序责任 |

没有 `control` 或没有确认限幅信息，就不判断输出近限；未提供合理变化率上限时，只给统计候选。未发现事件也不证明系统完全正常。

证据图：一张实际卡片展开图，突出“检测到的现象”“尚不能确定的原因”和定位后的图表。应能读出规则阈值，避免只展示红色警告。

## 第 08 页｜A/B 实验：把可比条件摆到差异前面

两份实验分别确认字段、单位和单次阶跃，并保存为独立快照。比较按各自 `t−t0` 对齐，用户确认共同观察时长；每侧指标仍使用自己的原始有效时间戳，不以对齐插值替换计算数据。

系统检查物理量、单位、目标变化、初值和评价配置，并收集对象、负载、采样和环境条件。条件未知或不同会显示限制；单位或评价口径不一致时不计算无意义差值。差值为 `B−A`，百分比为 `100×(B−A)/abs(A)`；分母为零或结果不可用时留空并解释。

**实际计算示例：闭环 PI A/B，非实测。** 同一一阶对象、初值、目标、采样与环境规则，仅 PI 参数不同。共同阶跃后窗口为 20 s，以下数值来自已记录的统一分析流程，不是手工调整曲线后的评分。

| 指标 | A | B |
| --- | ---: | ---: |
| 时间加权 RMSE / 1 | 0.232987 | 0.110327 |
| IAE / 1·s | 2.485372 | 0.490000 |
| 上升时间 / s | 6.106616 | 1.075475 |
| 超调 / % | 0 | 0 |
| 目标调节时间 / s | 11.482420 | 1.938512 |

在该对象与条件下，B 的所列响应时间和跟踪误差更小，超调相同；这不是对真实设备参数的推荐，也不能推出 B 在所有负载下更好。值源：README 的闭环 A/B 验收表及 `docs/acceptance/stage8-summary.json` 指向的验收记录。最终材料以重新生成的报告值为准。

证据图：实际对齐响应图 + 共同窗口及条件栏，曲线图必须标注仿真来源和横轴 `t−t0 / s`。

## 第 09 页｜AI 的核心作用：调度分析，而不是编造计算

AI 的作用是理解“分析这个实验”“只看 2～5 秒”“比较超调和响应时间”等问题，决定需要哪个已实现工具，组织后续追问，并把实际结果转成有依据的解释。CSV、指标和事件始终由本地程序计算。

**执行闭环：**用户问题 → 展示将发送的有限摘要并授权 → 模型选择工具 → 应用校验与执行 → 返回结构化结果 → 模型选择证据与解释类别 → 程序校验、渲染数字和来源。

| 白名单工具 | 复用的实际能力 |
| --- | --- |
| `profile_data` | 读取实际质量摘要与可用区间 |
| `analyze_run` | 按指定范围重新计算已确认口径下的性能 |
| `detect_events` | 按确认规则重新检测选段内现象 |
| `compare_runs` | 按共同窗口从两份原始有效数据重新比较 |

接口优先适配通义千问官方兼容工具调用形式，通过服务端的 `LLM_PROVIDER / LLM_BASE_URL / LLM_MODEL / LLM_API_KEY` 配置，不把模型名写死在业务计算中。当前使用 OpenAI Python SDK 访问百炼兼容 Chat Completions 的 `tools / tool_calls`，SDK 名称不代表调用 OpenAI 模型。

**真实单次联调通过：**2026-09-06，在用户逐轮授权后，北京 qwen-plus 对公开 PI A 的“分析实验A”实际调用 `profile_data`、`analyze_run`、`detect_events`。本轮共3次模型请求与3次工具调用；第2次响应被证据校验拒绝，有限纠正1次后第3次响应通过。不是3轮用户追问。无配置时仍显示“AI 未配置”，全部本地分析可用。记录见 `docs/acceptance/live-ai-summary.json`，不以测试替身冒充在线模型。

## 第 10 页｜AI 证据约束：一句事实要落到具体结果

答案分为“测得事实、候选解释、下一步验证、限制、证据引用”。测得事实仅允许引用 `result_id` 与指标键或 `event_id`；数值、单位、差值和比例由程序从对应结果中渲染，模型不另填一套数字。

每条引用需要同时满足：属于当前会话、本轮工具执行、当前实验及配置，并确实存在。不存在、越权、旧配置或旧轮次的证据会被拒绝。更换文件、单位、区间、阈值或共同窗口，会撤销旧上下文、证据和授权。

当用户追问“只看其中 2～5 秒”时，相关工具必须重新计算。若该段不包含完整确认阶跃，就只返回可计算的跟踪指标与响应限制，不沿用上一段的上升时间。

第一版使用受控解释模板：模型选择解释和验证类别，程序生成中文表述。它不能回答任意开放式控制理论问题，也不能自动断言 PID 根因或生成可直接下发的设备参数。

发送前逐轮授权；默认不上传整份 CSV、原始行、文件名、备注、路径或实验条件原文。只允许当前会话授权实验的四个只读工具，禁止任意 Python、Shell、文件路径、安装和设备连接。轮数、工具数、超时、重试和纠正均有上限，重复调用被识别。

本页以真实记录转写和程序取值展示本轮单实验联调；视频另展示实际工具与证据界面截图。模型请求顺序及全部结果ID见 `docs/acceptance/live-ai-summary.json`。`analyze_run` 的跟踪区间为0–21秒，响应区间1–21秒：RMSE_t=0.22841650252730472，IAE=2.495371903162585，上升时间6.10661623679659秒，超调0%，目标调节时间11.482420282338806秒。PDF由脚本直接读取记录值，不能把该跟踪区间与A/B的1–21秒混算。测得事实、候选解释、验证建议、限制与证据引用仍分区。

## 第 11 页｜开发工具与技术实现：保留清楚的计算边界

实际验证环境为 Windows x64、Python 3.12.14，使用项目独立虚拟环境与锁定依赖。Streamlit 提供单体交互页面，pandas / NumPy 处理数据和计算，Plotly 提供曲线，Pydantic 校验结构，pytest 与 AppTest 验证数值和页面。SciPy 是锁定分析依赖，当前核心指标未依赖复杂 SciPy 求解。

| 模块 | 职责 | 与其他层的边界 |
| --- | --- | --- |
| `core/` | CSV、质量、指标、现象、快照与对比 | 不依赖 Streamlit 或模型 |
| `ui/` 与 `app.py` | 工作台、确认动作、会话和证据展示 | 不在页面回调里重新定义指标 |
| `agent/` | 配置、适配、白名单工具、循环与证据 | 复用 core，不执行任意代码 |
| `reports/` | 核验、冻结快照、HTML/JSON/CSV | 三种格式来自同一快照 |
| `projects/` | 有界归档、摘要/版本校验、恢复重算 | 不执行包内代码，不信任旧结果 |
| `examples/`、`tests/`、`scripts/` | 可复现数据、验证、环境安装启动 | 示例来源与真实联调状态明确 |

当前没有引入前后端分离、向量数据库、用户登录、实时串口、自动下发 PID 或模型训练。保持轻量部署和可理解代码边界，便于课程环境本地运行、审查和复算。

可视结构：左侧“用户与会话”，中间“UI→core / agent”，右侧“冻结报告与项目包”；云模型连接只来自 agent 适配器并经过授权。

## 第 12 页｜报告与保存：结果离开页面后仍可核对

HTML 报告包含项目/实验名称、来源声明、数据摘要、映射/单位、区间、阈值、版本、质量问题、指标/交互图、异常证据、A/B 条件与限制，以及可用的 AI 解释和验证建议。程序计算与 AI 辅助解释明确分区；没有 AI 也能正常导出并显示“AI 未参与”。

页面与 HTML、JSON、指标 CSV 共用生成时冻结的结果。改页面配置后提示旧快照并要求重新生成，不把新配置拼到旧数值上。HTML 只内嵌一次必要 Plotly 脚本，无 CDN 依赖；报告不嵌入整份原始 CSV。中文、缺失指标、不可信备注和脚本结束标签均纳入安全测试。

`.labproj` 项目包另保存完整原始 CSV、确认配置与最多 8 份历史快照。上传恢复时校验结构、摘要、版本，并重新执行分析和对比；全部通过才替换当前会话。历史报告仅作为只读 JSON 归档，不能自动变成当前 AI 证据。

项目包需显式下载，未加密，摘要只校验一致性、不证明作者或实测真实性。AI 密钥、授权、会话身份和活动聊天证据不恢复。报告文件与项目包承担不同任务：前者用于阅读、引用，后者用于重算和继续工作。

## 第 13 页｜完整使用说明：第一次运行到再次复盘

**安装和启动。** 新电脑先安装 Python 3.12，在项目根目录执行 `scripts\install.cmd`；安装成功后执行 `scripts\start.cmd`，打开 `http://127.0.0.1:8501/`。已有项目环境可以直接启动。安装器检查独立虚拟环境和锁定包，失败明确退出，不修改系统设置或打印密钥。

**准备数据。** 使用“实验分析 → 加载示例”熟悉流程，或上传自己的 CSV。必需列是时间、目标、实测；核对映射、时间单位和共同物理单位，再确认检查。若有断点，明确选择连续有效片段。

**分析与比较。** 核对单次阶跃时刻、前后目标和基线，确认后查看指标；在异常证据区展开并聚焦事件。比较时分别保存 A/B 快照，再到“实验对比”确认条件和共同窗口后计算。

**可选 AI。** 在本地 `.env` 或服务器环境填写四项模型配置并重启；不要在聊天中提交密钥。进入 AI 区选择实验，输入问题，核对将发送的摘要，逐轮授权并点击发送。未配置或请求失败时使用本地分析，不伪造模型回复。

**导出与继续。** 到“报告预览”生成快照并下载 HTML、JSON、CSV；关机前在项目区生成并下载 `.labproj`。下次上传、校验、确认恢复。清空仅影响当前会话，不能删除已经下载到本机的文件。

故障处理：无法启动先检查终端错误和 Python 版本；端口占用可使用 `--port 8502`；改代码后完整重启；报告旧配置提示需要重新生成；CSV 导入失败先核对编码、分隔符、字段和上限。完整命令见 README。

## 第 14 页｜数值与工程验证：用可以复查的记录说话

指标测试使用独立解析基准：阶跃后 `y(t)=1−exp(−t)`、初值 0、目标 1，理论 10%–90% 上升时间为 `ln(9)≈2.197225 s`，2% 目标调节时间为 `−ln(0.02)≈3.912023 s`，超调为 0。期望值直接来自数学定义，交点容差依据采样间隔，不能调用被测函数生成期望值。

边界测试涵盖负向阶跃、非零初值、静态目标、未到达、持续波动、非等间隔、短记录、数据断点，以及 RMSE/IAE 的独立解析或手算案例。不可计算状态、会话隔离、证据失效、白名单与越权、报告快照和注入防护均有测试。

## 第 15 页｜应用前景与商业模式：从教学验证开始

当前作品定位为本地实验复盘工具。适合先在一门课程、一个学生项目或一套公开实验数据上验证：同一日志能否被不同使用者按一致口径复算？质量问题能否被准确定位？报告是否保留了真实限制？这些问题比未经实测的效率承诺更可检验。

**拟验证的应用场景：**

- 控制课程实验：形成“原始数据—确认口径—数值结果—证据解释”的作业材料。
- 电机与机器人学生项目：离线复盘阶跃日志，对比同条件下的参数实验。
- 教师/助教核对：读取结构化结果和可追溯报告，定位口径不一致的环节。当前不含批量评分或教学管理。

**商业模式是后续假设，尚无客户或收入验证：**个人本地版可作为低门槛体验入口；面向实验室或课程团队，可探索部署支持、培训、课程示例与数据规范服务；更进一步的机构功能需在真实需求与成本验证后开发。不得将这些方向列为当前已上线能力。

验证路径：招募获同意的试用者 → 收集去标识化任务与错误反馈 → 预先约定正确性、可复算性和任务完成时间的测量方法 → 对比实际记录 → 再决定协作、机构部署或其他功能。市场规模、收费价格、收益与提效比例目前不作无依据估算。

价值主张：减少单位、窗口和证据口径不一致造成的分析风险，帮助学生把“看起来如此”写成“在这些数据与条件下得到此结果”。实际收益仍需用户试验验证。
