# 受限工具 Agent · 第五阶段

所有原有数值计算保持在 `core/`，第五阶段增加会话内适配、模型请求循环和证据展示。数值定义、阈值和积分规则继续以 [METRICS.md](METRICS.md)、[EVIDENCE.md](EVIDENCE.md)、[COMPARISON.md](COMPARISON.md) 为准，不改变口径。第六阶段已实现报告导出，见 [REPORT_FORMAT.md](REPORT_FORMAT.md)。2026-09-06已通过北京 `qwen-plus` 的单次、单实验真实联调，范围与证据见本文末尾及 [live-ai-summary.json](acceptance/live-ai-summary.json)。

## 四个已实现工具

工具由Pydantic验证JSON；额外字段、非法工具、非有限/倒置区间、越权ID均拒绝。模型不能传 `session_id`、文件路径、代码、确认开关、PID参数或任意配置覆盖。

| 工具 | 参数与实际执行 |
| --- | --- |
| `profile_data` | `experiment_id`；读取实际质量报告的行数、时长、问题计数/代码及最多20个有效片段，不发送原始行值 |
| `analyze_run` | `experiment_id`、可选 `time_range={start_s,end_s}`、`options.include_response`（默认true）；调用 `analyze_performance` 按原始时间戳重算；区间是绝对秒 |
| `detect_events` | `experiment_id`、可选time_range、空options；沿用已确认EventConfig调用既有检测；新范围限制原始行/有效片段后重新执行，不仅过滤旧事件列表 |
| `compare_runs` | `experiment_a`、`experiment_b`、可选 `options.common_duration_s`；两者必须是确认快照，共同窗口不超过页面本轮授权上限，调用 `compare_experiments` 从各自原始点重算 |

分析范围必须位于页面已确认的同一连续有效片段内，不跨缺失、重置、倒退或间隔断点。实际首尾是落入请求范围的原始点；不足两点拒绝，不制造边界采样点。`analyze_run` 仅在新范围完整包含原已确认的单阶跃段/基线时计算响应；否则返回实际跟踪指标及响应不可计算说明，不借旧范围响应拼接答案。要更改确认阶跃、阈值或初值，回本地页面确认后再问。

各工具均分配新result_id，保存来源SHA-256、当前配置指纹、原生计算范围/规则、适配器版本及底层算法版本。指标保持有限数值或None和明确状态/原因。A/B的差值和百分比全部由既有比较程序产生；分母为零或不可比时保持None。

## 会话、授权与多轮

应用从当前 `st.session_state` 注入随机会话身份，只授权AI区选中的A/B。上下文深复制当前已确认实验或已保存快照，无进程共享可变实验缓存。同名不同内容由原始摘要和实验身份区分。数据、映射、单位、性能/事件配置、原始选段、确认阶跃、条件或共同窗口变化，撤销旧上下文、证据和授权。相同实验ID的不同配置版本不能同时充当A/B，须避免指代歧义。

AI区的实验条件初值来自快照，可在“本轮实验条件（仅本地核对）”补充；独立于本地对比页条件输入，不修改原快照。自比使用同一份条件。发往模型的仅为已知标记和程序核对的match/mismatch/unknown，不发送条件原文。

每个问题先成为草稿。应用展示目的地址/模型、问题、有限历史、所选实验字段语义/单位/来源标签、原始摘要标识、选段、确认阶跃与阈值配置，以及工具摘要上限；需本轮勾选并点击发送。勾选本身不发请求。授权指纹绑定会话、问题、历史、数据/配置和发送目的；追问重新授权，不继承上轮勾选。

默认不发送整份CSV、原始行值、文件名、任意列名、备注、物理量名称、实验条件原文或路径。只发送规范字段键，单位经长度/字符过滤，来源标签为程序固定声明。问题正文由用户自行填写且会发送，已知Key或常见凭据形态会被拒绝；不把任意用户问题都视为已自动脱敏。

执行顺序是实际模型请求→模型选择工具→白名单校验和执行→结构化结果回传→模型选择证据及解释→程序校验/渲染。模型也可选择澄清，不编造工具进度。历史仅保留通过结构校验的有限问答，不保存原始无效模型正文或思维链。每轮事实必须来自本轮工具结果；旧引用不能冒充新计算。对于“2～5秒”“2到5秒”等阿拉伯数字明确区间，应用另行核验本轮证据的请求范围一致；复杂多区间需要澄清，不保证识别任意自然语言时间描述。

重复规范化的工具名+参数或重复调用ID会阻断循环；工具/轮次/重试/纠正/超时/上下文上限见 [配置文档](LLM_CONFIGURATION.md)。没有Python、eval、exec、Shell、任意路径读取、安装、设备连接、写原始文件或下发参数能力。

## 答案和证据

最终必须符合 `AgentAnswer`：测得事实、候选解释、下一步验证、限制、证据引用，另可有澄清类别。测得事实只含 `result_id` 加 `metric_key` 或 `event_id`；不得提供value、单位、自由“事实”文字。所有引用必须在evidence_references中声明，属于本会话/本轮/当前配置，且确实存在。

第一版采用**受控解释模板**：模型选择有限的候选解释、验证步骤和限制类别，程序填写中文文案；不直接展示模型自由文本。这能阻止模型在解释段夹带编造数字、根因断言或设备参数，但解释范围有限，不能当作开放式控制理论问答。输出不合法时有限纠正，之后明确降级，保留实际工具结果供本地展开核对，不补全不存在的事实。

输出近限候选解释必须绑定control_limit事件；记录链路候选必须绑定data_record事件或正的实际质量问题计数。其他解释也只能作为候选，不能证明原因。界面始终附带归一化口径和观测/因果限制：不是标准stepinfo，不确认PID错误、传感器故障、积分饱和，不宣布绝对优胜。

## 自动测试与手动验收

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pytest tests/test_agent_tools.py tests/test_agent_runner.py tests/test_llm_provider.py tests/test_agent_ui.py -q
```

`tests/conftest.py` 为自动测试清空LLM_API_KEY并阻断socket连接。模型替身只在 `tests/agent_fixtures.py`；正式页面只构造QwenProvider。MockTransport验证真实SDK生成的HTTP URL、tools请求、模型配置、tool_call_id语义、错误/超时/重定向边界，不消耗API。脚本替身验证重算、非法工具/越权、伪造或失效引用、循环、有限纠正和数据诱导；AppTest验证页面摘要授权、新范围、对比、自会话隔离和本地能力。

1. 无密钥启动：三个本地入口可用，加载示例并确认字段后显示质量/曲线/指标，AI区显示“AI 未配置”，聊天和发送禁用。
2. 本地配置密钥并重启：输入“分析实验A”。核对摘要前不应有模型执行记录；勾选后仍不发送，点击发送才调用。
3. 展开本轮记录和证据，逐个用result_id/指标键核对程序计算。不要把只有模型配置已读取当成远程验证通过。
4. 追问“只看其中2～5秒”，重新授权，检查新的analyze_run参数和新result_id；证据注明实际原始点范围。该范围不含完整阶跃时响应指标不会沿用。
5. 分别加载/确认闭环PI A/B的字段和单次阶跃、保存快照，在AI区选择两份快照及共同时长，核对条件。问“与实验B比较超调和响应时间”，检查compare_runs和程序差值；零超调的百分比应不可用。
6. 改事件阈值/条件/单位/选段后，旧证据必须失效，待发送草稿需要重新授权。遇到工具失败或模型格式错误应明确报错/降级，不出现伪造结论。

2026-09-06，用户授权在正式页面向北京 `qwen-plus` 提问“分析实验A”。公开 PI A 数据为闭环仿真、非实测，共1051行、0–21秒；确认阶跃 `t0=1s,r0=0,r1=1,y0=0`。模型共请求/响应3次，实际执行 `profile_data`、`analyze_run`、`detect_events` 各1次，其中分析与事件工具显式使用0–21秒。第二次响应的证据校验拒绝，应用有限纠正1次后，第三次响应通过校验并显示程序渲染的事实。没有编造工具进度，也没有为了成功省略证据验证。

此次成功覆盖一次问题内部的工具循环，**不等于已验收用户多轮追问**。上述第4步真实区间追问、第5步真实 AI `compare_runs` 尚待单独授权验证；首次错误配置导致的认证失败也独立保留，不计为成功。全部真实调用不计入离线测试数量。未测试真实设备、生产部署、多用户压力、其他Qwen地域/模型或开放式答案质量。浏览器断开/服务重启后会话数据和AI记录不持久化。
